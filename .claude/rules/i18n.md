# Locales, routing, SEO and search

The native language (locale) is the language of the UI, explanations and translations. German is the language being learned and is never a locale.

## Locales

- Locales are defined in one place, `src/i18n/locales.ts`: `code`, `name` (in its own language), `default`, `ready`, `dir` (`ltr` | `rtl`), `ogLocale` (e.g. `en_US`), `font` (see `.claude/rules/fonts.md`). Adding a language = an entry + translations + its UI strings registered in `src/i18n/ui/index.ts`, no other code changes; the steps are in `docs/adding-a-language.md`.
- Pages are `[...locale]` rest-parameter routes (`src/pages/[...locale]/…`) over `locales.ts`, so a new locale needs no page files.
- `ready: false` locales are built for preview but hidden from the picker, sitemap and search, and their pages get `noindex`.
- Routing: default locale without prefix (`/a2/perfekt/`), others with prefix (`/ru/a2/perfekt/`). Same slugs in every locale. No automatic redirects and no language hint or banner: search engines route visitors through `hreflang`, and the picker is always visible.
- `<html lang dir>` come from the locale. Every German fragment is wrapped with `lang="de"`.
- UI strings: `src/i18n/ui/en.ts` is the source of truth; other locale files `satisfies UiStrings`, so a missing key is a type error. Components use `t(locale, key)`.
- 404 page per locale (`src/pages/[...locale]/404.astro`): built to `404.html` and `<code>/404.html` (the `notFoundPages` integration in `src/config/not-found-pages.ts` moves them out of `404/index.html`), so Cloudflare serves the nearest one. It has no canonical or hreflang, and its picker links to each locale's home.
- Language picker: a `<details>` disclosure with plain links to the same page in the other locale, language names in their own language (`name`), no flags, the choice not stored. A small inline script in `LanguagePicker.astro` closes it on an outside click or Escape.

## SEO

- `hreflang` alternates for all ready locales plus `x-default` → English; canonical per locale; every page has its own title and description (`Base.astro` props).
- Open Graph: `og:locale` + `og:locale:alternate`, `og:type` `article` on topic pages, no image yet.
- JSON-LD from `src/lib/seo.ts`: `WebSite` (home), `BreadcrumbList` (level pages), `LearningResource` + `BreadcrumbList` (topic pages).
- Sitemap: `@astrojs/sitemap` with alternates for ready locales; `inSitemap` (`src/lib/seo.ts`) leaves out noindex pages. `robots.txt` (`src/pages/robots.txt.ts`) allows everything and names the sitemap.

## Search (Pagefind)

- `pnpm build` runs `pagefind --site dist` after `astro build`. Only topic pages of ready locales are indexed (`data-pagefind-body` on the article; badges are `data-pagefind-ignore`). One index per language from `<html lang>`; German examples are on every locale's page, so German words are found from any locale.
- The header button (`Search.astro`) and Cmd/Ctrl+K load the Component UI (`/pagefind/pagefind-component-ui.js` + CSS) on first use and open its `<pagefind-modal>`; nothing is loaded before. Pagefind translates its own strings from `<html lang>`.
- Themed only through `--pf-*` variables mapped to our tokens (`global.css`, `html:root` to beat Pagefind's `:root` defaults).
- Cloudflare allows 20,000 static files per deployment on the free plan, and Pagefind adds many: watch the count as topics and locales grow.
