Deutscherl architecture

A website for learning German grammar with an Austrian angle. Explanations in the learner's native language: English and Russian in the pilot. Levels A1 and A2 with five topics each, a dictionary, multiple-choice and word-order exercises. No accounts, no server code, no cookies.

The source of truth is CLAUDE.md in the repository; the decision history is in docs/decisions.md. This page is an illustrated snapshot from the planning phase.

Core idea: everything is built ahead of time

The whole site is turned into static files at build time: content validation, dictionary queries, rendering pages in every language and the search index. Visitors get finished HTML from the CDN. Regular pages carry only a couple of tiny inline scripts; exercises load when the visitor scrolls to them.

Layers

Each layer only knows about the one below it, so layers can change independently.

InteractionSvelte islands and inline JS

Svelte only where real interactivity is needed: exercises and the dictionary filter. Theme, language picker and language hint are a few lines of plain inline JavaScript. Search loads when opened.

PresentationAstro components

Layout variant A and MDX components: <InShort>, <RuleTable>, <Example id>, <AustrianNote id>, <Word id>, <SponsorSlot>. Page transitions use native CSS View Transitions.

Logicsrc/lib, plain TypeScript

Item selection with seeded randomness, answer checking with regional variants and alternative word orders, hashes for content review. No DOM, fully unit-tested.

Datatext files in git

Topics (MDX and YAML), per-language translations, review state, the dictionary as JSONL with manual override files. SQLite is generated from them at build time.

Qualitycross-cutting

Language check, Biome, astro check, content and review checks, translation coverage, Vitest, Playwright with axe and snapshots, JS budget. Deployment only after every check passes.

Everything people edit is a text file, so every change shows up in the pull request diff. Everything generated stays out of git. Everything is in English except localization files.

Content model

Core principle: German text is stored exactly once, in german.yaml, and shared by every language. Everything written in the learner's native language lives in that language's own files. Translators never touch German files, and a new translation never resets the German review.

FileContentsEdited by
meta.yamlLevel, category, order, reading time, sourcesTopic author
german.yamlExamples, choice items, word-order items, Austrian notes — German onlyAuthor, teacher's corrections
en.mdxCanonical explanation: title, "In short", rule, table, <Example id="e1" /> referencesAuthor
ru.mdxThe same in Russian, translated from the English meaningTranslator
i18n/<locale>.yamlExample translations, why texts, word-order translations, note translations — by idTranslator
review.yamlBase and translation statuses, reviewers, hashes, basedOn, historyScript only
# german.yaml (excerpt)
choice:
  - id: c7
    text: "Ich ___ gestern lange gesessen."
    answer: habe
    options: [habe, bin]
    alsoCorrect:
      - { value: bin, region: AT }
wordOrder:
  - id: w1
    parts: [ich, habe, Pizza, gegessen]     # neutral case: no hint
    accept:
      - [Pizza, habe, ich, gegessen]
    punctuation: "."

# i18n/en.yaml (excerpt)
choice:
  c7:
    why: "Germany: habe gesessen. Austria and southern Germany: bin gesessen."

Where rules are checked

Zod in Content Collections validates the shape of each file. Everything that spans files (ids used in MDX exist, every ready language has every key, the answer is among the options, hashes match) is checked by a separate script, validate-content.ts: Zod only sees one file at a time.

Native language and fonts

The learner chooses the language grammar is explained in. German is always the language being learned and is never a site language.

  • One list of languages. locales.ts: code, name in the language itself, ready, writing direction dir and font. A new language starts with ready: false: its pages are built but hidden from the picker, sitemap and search.
  • URLs. English without a prefix, others with a prefix, same slugs in every language. The picker is a plain link to the same page.
  • No redirects. If the page language differs from the saved choice or the browser language, a small dismissible hint appears.
  • Outdated translations. review.yaml records which version of English and German each translation was written against. If they change, the translation drops back to draft and shows up in review:status.
  • Ready for right-to-left. Logical CSS properties only (ms-, pe-, start, end) from day one, so Arabic or Hebrew later won't require a layout rewrite.
  • Markup. <html lang dir> from the page language, German fragments marked lang="de", hreflang for every version.
  • Repository language. Native-language text only in localization files; a CI check rejects non-Latin letters anywhere else.

Fonts

Atkinson Hyperlegible Next has no Cyrillic: its Fontsource package only ships latin and latin-ext. So each language gets its own font.

Content review

Each topic is reviewed in two parts, so every part is checked by someone who can actually judge it. The German teacher verifies the German content and the canonical English explanation. Each translation is reviewed by a fluent speaker of that language against the verified English page; for Russian, that is the owner. Nobody needs to know German and Russian at the same time.

ScopeFilesStatusesChecked by
basemeta.yaml, german.yaml, en.mdx, i18n/en.yamldraft → reviewed → verifiedOwner reads, German teacher verifies
translation (per locale)ru.mdx, i18n/ru.yamldraft → reviewedFluent speaker, compared with English

Badges say exactly what was checked

PageBadge
English"Checked by a teacher" when base is verified and unchanged, otherwise "Draft"
Russian"German checked by a teacher" (base verified) + "Translation reviewed" (translation reviewed against the current base), always with a link to the English version; otherwise "Draft"
  • Typo without reset. pnpm review:minor a2/perfekt ru --reason "typo in why c3" updates the hash, keeps the status and adds a history entry. Only the owner runs it.
  • Overview. pnpm review:status lists every topic with base status, translation status per language and outdated translations.

Dictionary

Text files are the source of truth. SQLite exists only for convenient queries at build time and is regenerated every time. A binary file in git can neither be merged nor reviewed in a PR.

Homonyms and URLs

A word is identified by lemma, part of speech and gender. The id and URL are built from them; umlauts and ß are kept, otherwise Maße and Masse would collide.

WordId and URL
der See (lake) / die See (sea)see-der / see-die
essen / das Essenessen-verb / essen-das
die Maße / die Massemaße-die / masse-die

MDX references words by id only: <Word id="see-der" />. Russian glosses come from the Russian Wiktionary and are matched by the same triple; ambiguous cases go to the import report instead of being guessed.

Life of a page

Moving to another page is a normal browser navigation animated with CSS @view-transition. Chrome and Safari animate it; other browsers simply open the page. No JavaScript involved.

Exercises

Word order

  • Drag and drop like everywhere else. Words move from the bank to the answer line, get reordered inside it, and can go back. Mouse drags immediately; on touch a 250 ms press starts the drag, a quick swipe scrolls. Keyboard and screen readers are supported by the library.
  • A proven library. svelte-dnd-action supports Svelte 5, a touch delay and multiple zones. About 13.5 KB gzipped.
  • No capitalization hints. Words are stored in neutral case; the first word is capitalized only after checking.
  • Several valid orders. Every valid order is listed in accept; comparison is by strings, so repeated words work.
  • "Check" button becomes active when the bank is empty. Punctuation sits after the line and is not draggable.

Multiple choice

One correct answer, except established regional variants in alsoCorrect: Austrian "bin gesessen" counts as correct, and why explains the difference.

Rounds

A round is 5 mixed items. Seen ids live in sessionStorage; the pool resets when exhausted. All randomness goes through a seeded generator, so tests are deterministic.

Accessibility. The target is WCAG 2.2 AA with one deliberate exception: word-order items have no single-tap alternative to dragging (criterion 2.5.7). This is recorded in the decision log and in the accessibility statement.

Analytics and legal

Analytics

Cloudflare Web Analytics: free, cookieless, small script. Shows visits, referrers, countries and Core Web Vitals. The script loads with defer and only in production; preview builds don't include it. The site token is not a secret and lives in site.ts.

Google Search Console is verified via a DNS record in Cloudflare, no code.

PostHog is postponed. The full library is about 98 KB gzipped, three times the JS of a whole exercise page. Worth revisiting if exercise-level events matter, e.g. which items people get wrong most often; it could then load after the first interaction.

Legal pages (Austria)

  • /impressum/ — disclosure under § 25 Mediengesetz for a small private website: owner's name, place of residence, purpose of the site.
  • /privacy/ — Cloudflare hosting, analytics, what is stored in the browser, text-to-speech via the Web Speech API, links to GitHub.
  • When ads arrive: banners are labeled as ads, and the Impressum is extended to the requirements for commercial sites.

Claude Code writes templates with TODO markers; the owner fills in and checks the facts.

Key decisions

The full list with reasons and rejected alternatives is in docs/decisions.md. The highlights:

Astro with Svelte islands

Almost every page is static. Astro ships no JavaScript by default, and Svelte compiles to small islands. Svelte is used only where it is truly needed.

German stored once, translations in per-language files

The teacher checks German once, translators never touch German files, and adding a translation doesn't reset the German review.

Split review with automatic reset

The teacher verifies German and the English explanation; each translation is reviewed against the verified English page by a fluent speaker. Hashes record exactly what was checked; any edit returns the affected part to draft, except logged typo fixes. Badges say exactly what was checked.

Functional tests on English only, no screenshot tests

All languages share the same code, so functional tests run on English pages; other languages get language-switching tests only. Screenshot comparisons are not used: they are costly to maintain and flaky, and functional tests plus axe catch the relevant breakage.

Dictionary in text files, SQLite generated

A binary file can't be merged or reviewed. Import output and manual edits are separate, so re-importing breaks nothing.

A font per language

The main font has no Cyrillic, and other scripts will come later. German blocks use one font everywhere, explanations use the language's font.

A proven drag-and-drop library

Long press versus scrolling on iOS is hard to get right by hand. svelte-dnd-action already solves it and adds keyboard and screen-reader support.

Minimal JavaScript

Theme and language are inline scripts; transitions are CSS. Astro's ClientRouter is not used because it adds JS to every page.

Deployment from GitHub Actions to Cloudflare

One build, deployment only after checks, a preview URL for every PR. Cloudflare's free plan allows commercial use.

Cloudflare Web Analytics instead of PostHog

Visits, referrers and speed are enough for the pilot. Cloudflare Web Analytics is free, cookieless and light. PostHog is postponed because of its size; it can come back for exercise-level events.

English-only repository except localization

Code, docs, templates, commit messages and tests are in English. Native-language text lives only in localization files, enforced by a CI check.

Open repository, PRs from collaborators only

Code under MIT, content under CC BY-SA 4.0, DCO sign-off. Mistakes are reported through GitHub issue forms.
