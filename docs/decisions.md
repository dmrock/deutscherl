# Decision log

One entry per decision: what was decided, why, and what was rejected. Newest at the bottom. Claude Code appends entries at the end of every stage.

Status: `accepted`, `pending` (waiting for the owner), `superseded by #N`.

---

## 1. Astro with Svelte islands — accepted

Content site, almost every page static. Astro ships zero JS by default; Svelte compiles to small islands. Rejected: Next.js (React runtime on every page), SvelteKit (kept as a possible later move; Svelte components are reusable).

## 2. Hosting on Cloudflare Workers static assets — accepted

Free plan allows commercial use (planned sponsor banners); fast CDN; room for a Worker or D1 later. Rejected: Vercel (Hobby plan is non-commercial). No Astro adapter: the build is fully static.

## 3. Deploy from GitHub Actions — accepted

One pipeline: checks first, then preview (`wrangler versions upload --preview-alias pr-<n>`) or production (`wrangler deploy`). A broken build never deploys, the build runs once. Rejected: Cloudflare Git integration (builds separately from CI checks).

## 4. English and Russian as native languages, data-driven locales — accepted

English default and unprefixed, Russian under `/ru/`. Locales in one config with `ready`, `dir`, `font`. No automatic redirects; a dismissible hint instead.

## 5. German single-sourced, translations in per-locale files — accepted

German lives only in `german.yaml`; each locale has its own MDX and `i18n/<locale>.yaml`. Translators never touch German files; translations don't reset German verification. Non-English files store `basedOn` to detect outdated translations.

## 6. Per-locale fonts — accepted

Atkinson Hyperlegible Next has no Cyrillic (Fontsource subsets: latin, latin-ext). Fonts are configured per locale; German content blocks always use Atkinson. Future scripts get their own font entry.

## 7. Russian font — pending

Candidates with Cyrillic: Golos Text, Inter, Noto Sans, Onest. Owner chooses after the comparison page in stage 2.

## 8. Page-level review with automatic reset — superseded by #20

Unit of review = topic × locale. `draft → reviewed → verified`; the teacher verifies the whole page. A content hash is stored at review time; any change resets the page to `draft` (pre-commit hook, enforced in CI). Typo fixes can keep the status via `review:minor --reason`, logged in history.

## 9. Dictionary: text files are the source of truth — accepted

`db/data/words.jsonl` (generated by import) + `db/overrides/*.yaml` (manual edits) in git; SQLite generated at build and gitignored. Reason: binary SQLite can't be merged or reviewed in PRs. Rejected: committed SQLite with an `editedManually` flag.

## 10. Dictionary ids and URLs — accepted

Identity `(lemma, pos, gender)`; slug = lowercase NFC lemma + article (nouns) or part of speech; umlauts and ß kept (`maße-die` ≠ `masse-die`). Rejected: transliteration (creates collisions).

## 11. Drag and drop with svelte-dnd-action — accepted

Proven library: Svelte 5, touch delay (`delayTouchStart: 250`), keyboard and screen-reader support, multiple zones. About 13.5 KB gzipped. Rejected: hand-rolled Pointer Events (hard to get long-press vs scroll right on iOS), SortableJS (no keyboard support).

## 12. WCAG 2.5.7 exception for word order — accepted (owner decision)

Word-order exercises use drag and keyboard input without a single-tap alternative. This is a known deviation from WCAG 2.2 AA; documented in the accessibility statement.

## 13. Regional answers in exercises — accepted

`alsoCorrect: [{ value, region }]` accepts established regional forms (e.g. Austrian "bin gesessen") as correct with an explanation.

## 14. Word order without capitalization hints — accepted

Parts stored in neutral case; first word capitalized only after checking. `accept` lists all valid orders; comparison by strings.

## 15. Minimal JavaScript — accepted

Theme, language picker and hint are inline vanilla JS. Page transitions via native CSS cross-document View Transitions (Chrome 126+, Safari 18.2+; others navigate normally). Rejected: Astro `<ClientRouter />` (JS on every page). Budgets enforced in CI: ≤ 3 KB on pages without exercises, ≤ 45 KB on topic pages.

## 16. Open source with controlled contributions — accepted

Public repo; code MIT, content CC BY-SA 4.0; DCO sign-off; PRs only from collaborators; issues via forms. "Report a mistake" uses GitHub issue forms only (no email).

## 17. Canonical URLs with trailing slash — accepted

Astro `build.format: 'directory'` + `trailingSlash: 'always'`, matching Cloudflare's default HTML handling.

## 18. Analytics: Cloudflare Web Analytics — accepted (owner decision)

Free, cookieless, small beacon; page views, referrers, countries, Core Web Vitals. Loaded with `defer`, production only. Google Search Console via DNS verification.
Postponed: PostHog (EU cloud, free tier). Full SDK ≈ 98 KB gzipped with cookieless mode, lite SDK ≈ 24 KB without cookieless mode — too heavy for the JS budget now. Revisit if exercise-level events (which items people get wrong) become important; then load it lazily after first interaction.

## 19. English-only repository except localization files — accepted (owner decision)

Code, docs, templates, commit messages and test names are in English. Native-language text lives only in localization files; `scripts/check-language.ts` enforces this in CI and pre-commit by rejecting non-Latin letters outside allowed paths.

## 20. Split review: teacher verifies German + English, translations reviewed against English — accepted (owner decision)

Russian ships at launch. A teacher who verifies whole Russian pages would need native German and fluent Russian, which is rare. So review has two scopes per topic:
- `base` (German content + English explanation): verified by a German teacher.
- `translations.<locale>`: reviewed by a fluent speaker of that locale (the owner for Russian) against the verified English page.
Each scope is hashed. Any base change resets base and every translation checked against the old base; a translation change resets only that translation. `review:minor` keeps the status for logged typo fixes. Badges state exactly what was checked (e.g. "German checked by a teacher" + "Translation reviewed", with a link to English). Rejected: a single "Checked by a teacher" badge on translated pages (misleading), and English-only launch (scored close; Russian chosen for the early Russian-speaking audience).

## 21. No visual snapshot tests — accepted (owner decision)

No Playwright screenshot comparisons. They need constant updating on design changes and are flaky across systems; functional tests and axe catch the relevant breakage. Layout risk from long Russian strings is covered by one functional check: no horizontal scrolling on a Russian topic page at mobile width.

## 22. Functional tests on English only — accepted (owner decision)

All locales share the same code, so exercises, navigation, search and accessibility are tested on English pages only. Other locales get language-switching tests only (picker, hint, lang/dir/hreflang/canonical, mobile overflow). Missing translations are caught by the `i18n-coverage` data check, not by tests.
